## 1. 引言

### 1.1 编写目的

本文档定义「AI 智能记账小程序」的完整需求基线，作为后续概要设计、数据库设计、接口设计、测试与验收的唯一依据。读者对象为产品负责人、开发人员、测试人员及后续维护人员。

### 1.2 项目背景

传统记账工具要求用户逐项选择金额、分类、渠道、日期，操作链路长，导致记账行为难以坚持。本项目通过大语言模型（DeepSeek）对用户输入的自然语言进行结构化抽取，把「说一句话」直接转换为一条标准账单记录，最大限度降低记账门槛。

### 1.3 文档范围

- 覆盖内容：功能需求、数据字典、非功能需求、核心用例、版本规划、需求跟踪矩阵。
- 不覆盖内容：具体代码实现、详细接口字段定义、数据库 DDL（分别见《02-概要设计说明书》《03-数据库设计说明书》《04-接口设计说明书》）。

### 1.4 术语与缩写

| 术语 | 说明 |
| --- | --- |
| openid | 微信用户在本小程序内的唯一标识 |
| NLP 解析 | 将自然语言文本抽取为结构化账单字段的过程 |
| 账单 | 一条记账记录（含金额、类型、渠道、分类、日期等） |
| 渠道 | 支付渠道，如微信、支付宝、现金、银行卡 |
| 分类 | 消费/收入归类，如买菜餐饮、交通出行 |
| AI 月报 | 由大模型生成的当月消费总结文本 |

## 2. 项目概述

### 2.1 产品定位

个人及家庭自用的智能记账工具。无商业化、无支付、无广告、无社交裂变。以「一句话记账」为核心差异化能力。

### 2.2 目标用户与画像

| 用户类型 | 特征 | 核心诉求 |
| --- | --- | --- |
| 主要用户（个人记账者） | 有记账意愿但嫌手动录入繁琐 | 说一句话即可完成记账 |
| 次要用户（家庭记账） | 夫妻/家庭成员共同记录家庭开支 | 共享账本、共同查看、AA 分账 |

### 2.3 核心价值

1. **低门槛**：自然语言直接记账，无需选择表单。
2. **可核对**：解析结果先预览、可修改，再落库，避免错账。
3. **有价值**：统计报表与 AI 月报让用户看懂自己的钱花在哪里。

### 2.4 运行环境与技术约束

| 层面 | 选型 | 约束说明 |
| --- | --- | --- |
| 小程序端 | 原生微信小程序 | 个人主体，类目「工具-其他工具」，无需认证 |
| 后端 | JDK 17 + Spring Boot 3.2.x + MyBatis-Plus | Spring Boot 3.x 强制要求 JDK 17+ |
| 数据库 | MySQL 5.6 | 需明确字符集、索引前缀、时间默认值限制 |
| AI 服务 | DeepSeek `deepseek-flash` | OpenAI 兼容接口，需 Json Output 保证结构化输出 |
| 部署 | 本地开发 → 云服务器 | 本地允许 HTTP 8080 调试；上线必须 HTTPS + 已备案域名 |

### 2.5 假设与依赖

- A1：用户具备微信账号，小程序已完成注册并通过审核。
- A2：已申请 DeepSeek API Key，且账户有可用余额/额度。
- A3：DeepSeek 服务可用；若不可用，系统必须降级为手动记账（见 F-52）。
- A4：V1 阶段不做多用户权限体系，鉴权以 openid 派生的 JWT 为凭据。
- A5：单用户账单量级预估 < 10 万条，V1 不引入分库分表。

## 3. 总体业务流程

### 3.1 首次登录流程

```
小程序启动 → wx.login 获取 code → 后端 /api/wx/login
  → 后端调用微信 code2Session 换取 openid
  → 若 openid 不存在则创建 user 记录
  → 签发 JWT 返回小程序并本地缓存
```

### 3.2 主流程：一句话记账（核心）

```
用户输入自然语言文本
  → 小程序 POST /api/bill/parse（携带 JWT + text）
  → 后端拼接字典化的系统 Prompt + 用户文本
  → 调用 DeepSeek Chat Completions（Json Output）
  → 后端解析 JSON → 字段合法性校验 → 字典归一 → 日期补全
  → 返回结构化结果（不落库）
  → 小程序弹窗预览，用户可修改任意字段
  → 用户确认 → POST /api/bill/save 落库
  → 账单列表与统计即时刷新
```

**关键设计点：解析与保存分离。** `parse` 接口只负责识别，不写库；只有用户确认后的 `save` 才写库。这样既保证了用户的可控性，也让 AI 解析失败不会污染数据。

### 3.3 解析失败兜底流程

```
调用 DeepSeek 失败 / 返回非法 JSON / amount 无法识别
  → 后端返回错误码（1002 / 1003 / 1004）并给出可用的部分字段
  → 小程序切换到「手动填写表单」模式，预填已识别字段
  → 用户手动补全后保存
```

### 3.4 账单查询与统计流程

```
账单列表页 → GET /api/bill/list（分页、时间倒序、条件筛选）
统计页     → GET /api/bill/stat/month（当月收支合计）
           → GET /api/bill/stat/category（分类占比）
```

| F-28 | 账单文件批量导入 | V2 | P1 | 导入微信支付/支付宝导出的 CSV 账单，批量解析入账 | 支持预览导入条数与失败明细；支持整体撤销本次导入 |

> 说明：原需求文档将「工资收入 / 转账其他」与支出分类混排，本版本拆分为按收支类型区分的字典表，避免统计口径混乱。字典支持后台维护，新增分类无需修改 Prompt 逻辑。

## 6. 非功能需求

| 编号 | 类别 | 需求描述 | 验收标准 |
| --- | --- | --- | --- |
| NF-01 | 性能 | 记账解析接口响应时间（含大模型调用） | P95 ≤ 5 秒；超时阈值 15 秒，超时即触发兜底 |
| NF-02 | 性能 | 列表与统计接口响应时间 | P95 ≤ 500 毫秒（1 万条账单量级） |
| NF-03 | 安全 | 密钥保护 | AppSecret、DeepSeek API Key、数据库口令仅存于后端配置，前端与代码仓库中不得出现 |
| NF-04 | 安全 | 鉴权 | 除登录接口外全部接口需校验 JWT；越权访问他人账单返回 403 |
| NF-05 | 安全 | 传输 | 生产环境全链路 HTTPS |
| NF-06 | 可靠性 | 降级能力 | DeepSeek 不可用时，记账主流程仍可通过手动填表完成 |
| NF-07 | 可靠性 | 幂等 | `save` 接口需支持幂等，防止用户重复点击产生重复账单 |
| NF-08 | 成本 | 调用成本 | 单条记账解析成本控制在可忽略量级；对相同文本做短时缓存，避免重复调用 |
| NF-09 | 兼容 | 数据库 | 适配 MySQL 5.6：字符集 utf8mb4、唯一索引字段长度 ≤191 或启用 `innodb_large_prefix`、时间字段由应用层写入 |
| NF-10 | 兼容 | 小程序 | 基础库 ≥ 2.30，兼容 iOS / Android 主流机型 |
| NF-11 | 可用性 | 交互容错 | AI 识别失败、金额为 0 等场景必须有明确提示并给出下一步动作 |
| NF-12 | 合规 | 个人主体小程序 | 不涉及支付、不收集敏感个人信息（仅 openid），类目「工具-其他工具」 |
| NF-13 | 可维护 | 配置化 | AI 模型名、超时时间、Prompt 模板、字典均需可配置，禁止硬编码 |
| NF-14 | 可观测 | 日志 | 关键链路（登录、解析、落库）需记录结构化日志，便于问题定位 |

## 7. 核心用例描述

### UC-01 自然语言记账（核心用例）

| 项 | 内容 |
| --- | --- |
| 用例编号 | UC-01 |
| 参与者 | 已登录用户 |
| 前置条件 | 用户已登录，JWT 有效 |
| 触发条件 | 用户在首页输入框输入文本并点击「记账」 |
| 主成功流 | 1. 小程序提交文本到 `/api/bill/parse`<br>2. 后端拼接 Prompt 并调用 DeepSeek<br>3. 后端校验并归一化字段<br>4. 返回结构化结果<br>5. 小程序弹窗预览<br>6. 用户确认<br>7. 小程序提交 `/api/bill/save`<br>8. 后端落库并返回账单 ID<br>9. 列表与统计刷新 |
| 扩展流 | 3a. 输出非法 JSON → 返回 1003，引导手动填写<br>3b. amount 无法识别 → 返回 1004，引导手动填写金额<br>2a. DeepSeek 超时 → 返回 1002，引导手动填写 |
| 后置条件 | 账单成功落库，可见于列表与统计 |
| 业务规则 | 未确认不落库；金额必须 > 0；分类/渠道必须命中字典 |

### UC-02 账单修改与纠正

| 业务规则 | 只能修改本人账单；修改后统计需实时重算 |

### UC-03 查看月度统计

| 项 | 内容 |
| --- | --- |

### UC-04 解析失败手动兜底

| 项 | 内容 |
| --- | --- |
| 用例编号 | UC-04 |

| 业务规则 | 兜底路径必须可用，不允许出现无法记账的死路 |

## 8. 版本规划与优先级汇总

| 版本 | 主题 | 包含需求 | 目标 |
| --- | --- | --- | --- |
| **V1** | 核心闭环（MVP） | F-11、F-12、F-21、F-22、F-31~F-34、F-41、F-42、F-51~F-54 | 一句话记账 → 确认 → 落库 → 查看统计，全链路可用 |
| **V2** | 录入效率与智能增强 | F-23~F-26、F-28、F-35~F-37、F-61、F-62 | 降低录入成本，提升识别准确率与可控性 |
| **V3** | 数据价值与协作 | F-27、F-43、F-44、F-71、F-81~F-83、F-91~F-93 | 让数据产生洞察，支持家庭协作场景 |

### 明确不做（Out of Scope）

| 功能 | 原因 |
| --- | --- |
| 记账排行榜 / 打卡社交 | 对工具类产品属伪需求，收益低且分散精力 |
| 智能硬件对接 | 投入产出比过低 |
| 商业化、广告、支付 | 产品定位为个人自用，且个人主体小程序不支持 |
