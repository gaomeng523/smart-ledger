## 3. 关键设计

### 3.1 五条设计原则（《02》§1.2）

1. **解析与落库分离：** `parse` 只产出待确认草稿，不写库；用户确认后 `save` 才落库。
2. **字典驱动：** 分类、渠道以字典表为准，Prompt 由字典动态生成。
3. **失败可降级：** 任何 AI 异常都回落到手动记账，主流程不断路。
4. **配置化：** 模型名、超时、Prompt、开关外置，禁止硬编码。
5. **面向演进：** V1 不过度设计，但为账本、资产、协作预留扩展位。

### 3.2 系统分层

| 层 | 组成 | 职责 |
| --- | --- | --- |
| 客户端 | 原生微信小程序 | 输入、预览、编辑、本地状态 |
| 接入层 | HTTPS/JSON、JWT 拦截器、全局异常、统一响应 `R` | 鉴权、校验、错误收敛 |
| 应用层 | 登录、账单、统计、字典、预算、报表等服务 | 业务流程编排、事务边界 |
| 领域/支撑层 | AiParseService、PromptBuilder、ParseResultValidator、DeepSeekClient、微信客户端 | AI 解析与第三方调用 |
| 基础设施层 | MyBatis-Plus、Caffeine、日志、定时任务 | 数据访问、缓存、可观测 |
| 存储/外部 | MySQL 5.6、DeepSeek API、微信开放平台 | 持久化与外部能力 |

包结构按 `common / config / interceptor / controller / service / ai / mapper / entity / dto / converter` 划分；Controller 不写业务，Service 承载业务，Mapper 只做数据访问。

### 3.3 AI 解析链路（核心）

```text
输入校验（非空、≤200 字）
  → 别名匹配（命中分类且能提取金额时跳过 AI）
  → 结果缓存（同用户 + 同文本 60s）
  → 限流（20 次/分钟）
  → PromptBuilder：拼接渠道/分类字典 + 今天日期
  → DeepSeek Chat Completions：response_format=json_object，temperature 0.2，max_tokens 256
  → ParseResultValidator：金额/收支/渠道/分类/日期/备注/置信度校验与归一
  → 记录 ai_parse_log（输入、输出、耗时、token、成功/失败）
  → 返回待确认草稿（不落库）
```

| 组件 | 职责 |
| --- | --- |
| `PromptBuilder` | 从字典表读取分类/渠道，生成系统 Prompt，确保模型只能从合法值中选择 |
| `DeepSeekClient` | HTTP 调用、连接 3s/读取 12s 超时、失败重试 1 次、异常转业务错误码 |
| `AiParseService` | 编排解析、别名、缓存、限流、日志、兜底 |
| `ParseResultValidator` | 字典命中、日期回退、金额归零、备注截断、置信度钳制 |
| `AiParseLogService` | 解析日志落库，失败不影响主流程 |

**兜底规则：**

- 超时/服务异常 → `1002`；输出非 JSON → `1003`；金额无法识别 → `1004`。
- 三种情况都返回可用字段，前端切手动表单并预填，保证「任何失败都能完成记账」。
- 日期非法或晚于今天 +1 天 → 回退今天；字典未命中 → 「其他支出/其他收入」。

### 3.4 MySQL 5.6 适配

| 限制 | 对策 |
| --- | --- |
| 字符集 | 使用 `utf8mb4`（5.5.3+ 已支持），避免 emoji 写入失败 |
| 索引前缀 | 需索引的字符串统一 `varchar(191)`，规避 COMPACT 行格式 767 字节限制 |
| 时间默认值 | 单表仅一个 `DEFAULT CURRENT_TIMESTAMP`；`create_time/update_time` 全部由 MyBatis-Plus `MetaObjectHandler` 填充 |
| 无 JSON 类型 | 解析结果拆为普通列；日志类数据用 `text` |
| 排序规则 | `utf8mb4_general_ci` |

### 3.5 幂等、事务、缓存与安全

| 主题 | 方案 |
| --- | --- |
| 幂等 | 小程序生成 `requestId`；`bill.request_id` 唯一索引；重复提交返回既有 `billId` |
| 重复检测 | 同用户、日期相差 ≤3 天、金额/渠道/分类相同 → 返回 `1005` + 候选；用户确认后 `force=true` + 新 `requestId` 重提 |
| 事务 | `save` 单条写入；导入按批次记录、单条失败不整体回滚；AA 分账主账单 + 明细同事务 |
| 缓存 | 字典 Caffeine 10 分钟；解析结果 60 秒；用户信息 5 分钟 |
| 安全 | JWT 携带 openid，服务端不信任前端 openid；越权 403；密钥不入前端；解析限流；HTTPS |

### 4.2 设计约定

- 表名小写下划线、单数；主键 `bigint unsigned auto_increment`。
- 金额 `decimal(10,2)`（账户余额 `decimal(12,2)`），禁止 float/double。
- 时间统一 `datetime`，由应用层写入，DDL 不设默认值。
- 逻辑删除 `deleted tinyint default 0`；状态 `status tinyint default 1`。
- 全库 `utf8mb4`；索引字符串 `varchar(191)`。
- 标签复用 `bill.tags` 逗号分隔，不单独建标签表。

### 4.3 关键索引与容量

| 索引 | 支撑场景 |
| --- | --- |
| `bill.idx_openid_date (openid, record_date)` | 列表分页、月度统计、重复检测候选 |
| `bill.idx_openid_category (openid, category_code)` | 分类统计、分类筛选 |
| `bill.idx_openid_channel (openid, pay_channel_code)` | 渠道筛选 |
| `bill.uk_request_id (request_id)` | 幂等防重 |
| `bill.idx_book_date (book_id, record_date)` | 共享账本（V3） |
| `ai_parse_log.idx_openid_time` | 解析日志检索 |

容量预估：单用户年增账单约 1,000~3,000 条，V1 不分表；`ai_parse_log` 建议保留 90 天后清理或归档。

## 5. 接口设计

### 5.1 通用约定

| 项 | 约定 |
| --- | --- |
| 基础路径 | `/api` |
| 数据格式 | `application/json; charset=UTF-8` |
| 鉴权 | `Authorization: Bearer <token>`；除登录外全部校验；token 7 天 |
| 成功响应 | `{ code: 0, message: "success", data, timestamp }` |
| 分页响应 | `{ total, page, size, pages, records[] }` |
| 日期/金额 | `yyyy-MM-dd` / `yyyy-MM-dd HH:mm:ss`；金额用 BigDecimal |

**错误码：**

| 区间 | 含义 | 示例 |
| --- | --- | --- |
| 0 | 成功 | — |
| 4xx | 客户端错误 | 400 参数、401 未登录、403 越权、404 不存在、429 限流 |
| 5xx | 服务端错误 | 500 系统异常 |
| 1xxx | 业务错误（HTTP 200） | 1001 微信登录失败、1002 AI 解析失败、1003 输出非法、1004 金额无法识别、1005 疑似重复、1006 导入格式错误、1007 解析过于频繁 |

### 5.2 接口分组

| 版本 | 接口 | 说明 |
| --- | --- | --- |
| V1（10） | `/api/wx/login`、`/api/dict/all`、`/api/bill/parse`、`/api/bill/save`、`/api/bill/list`、`/api/bill/detail`、`/api/bill/update`、`/api/bill/delete`、`/api/bill/stat/month`、`/api/bill/stat/category` | 核心闭环 |
| V2 | `/api/template`（CRUD）、`/api/template/use`、`/api/alias`（CRUD）、`/api/budget`、`/api/bill/import`、`/api/import/rollback`、`/api/bill/tag/suggest` | 模板、别名、预算、导入、标签 |
| V3（已实现） | `/api/bill/stat/trend`、`/api/report/month`、`/api/export/bill` | 趋势、AI 月报、导出 |
| V3（规划） | `/api/ocr/receipt`、`/api/book`、`/api/book/join`、`/api/book/split`、`/api/debt` | OCR、共享账本、AA、借贷 |

> 代码实际还暴露了订阅、心愿储蓄、消费洞察、图片上传、H5 登录、健康检查等接口，文档尚未收录，详见 §9。

### 5.3 第三方对接

| 服务 | 用途 | 关键点 |
| --- | --- | --- |
| 微信 `code2Session` | code 换 openid | 失败映射 1001；session_key 不使用、不落库 |
| DeepSeek Chat Completions | 自然语言结构化 | `response_format=json_object`；Prompt 必须含「JSON」；429/5xx 转 1002 |

### 5.4 核心 DTO

- `BillDTO`：账单详情/列表项（含分类/渠道名称、标签数组）。
- `ParseResultDTO`：解析草稿（amount、billType、channel、category、date、remark、confidence、missingFields）。
- `StatMonthDTO`：月度收入/支出/结余/笔数。
- `StatTrendDTO`：近 6/12 月收支、环比、同比。
- `MonthReportDTO`：AI 月报（summary、highlights、suggestions、真实 stats、aiGenerated）。

## 6. UI 与交互设计

### 6.1 视觉方向

- **风格：** 奶油马卡龙（Cream Macaron）——奶油白底、柔和暖调、大圆角、极浅暖色阴影、圆润图标。
- **主色：** 微信绿 `#07C160`；支出蜜桃红、收入绿；奶黄/蜜桃粉/薄荷只做点缀，不承载信息文字。
- **设计令牌：** 颜色、圆角（24/32/999rpx）、阴影（3 个）、间距（4rpx 网格、8 档）集中在 `app.wxss`。
- **可读性：** 金额等宽数字（tabular-nums）；正文 ≥24rpx；最小热区 88rpx；低置信度必须提示。
- **动效：** 单次反馈 ≤600ms；光环/挥手/思考点为低频循环；遵循「减弱动态效果」。

### 6.2 吉祥物「萌萌」

- 形象：云朵身体 + 硬币光环 + 钱包尾巴；纯 WXSS 绘制，默认不请求 PNG。
- 8 个状态：`idle / expect / thinking / success / wow / empty / offline / shine`，仅出现在规定位置，同屏最多 1 个。
- 代表性交互：保存成功后输入文字向萌萌收缩消失（620ms），萌萌切 `success` 并冒出「啊呜～」，即「吃掉账单烦恼」。

### 6.3 页面与组件

| 版本 | 页面 | 说明 |
| --- | --- | --- |
| V1 | P-01 首页、P-02 账单列表、P-03 详情/编辑、P-04 统计、P-05 我的 | 四个 tab + 详情页 |
| V2 | P-06 模板、P-07 预算、P-08 导入、P-09 别名 | 均从「我的」进入 |

**组件：**《07》§5 列 12 个——`bill-item`、`parse-preview`、`bill-form`、`dict-picker`、`month-picker`、`empty-state`、`skeleton`、`donut-chart`、`mascot`、`tag-chips`、`filter-panel`、`template-item`；代码实际另有 `category-icon`，共 13 个。

### 6.4 关键交互

| 场景 | 规则 |
| --- | --- |
| 解析成功 | 半屏预览弹窗，字段可改；未确认不落库 |
| 解析失败（1002/1003/1004） | 切手动表单，预填可用字段；1004 自动聚焦金额 |
| 疑似重复（1005） | 弹窗展示候选；确认后 `force=true` + 新 `requestId`；取消不落库 |
| 401 | 清除 token → 静默重登 → 自动重放 1 次；并发登录加锁 |
| 保存防重 | 按钮立即禁用并 loading；同一草稿复用 `requestId` |
| 字典缓存 | 本地 10 分钟；过期重新拉取 |

### 6.5 验收要点

《07》§10 给出 20 条体验验收，覆盖：冷启动可输入 ≤1s、解析中不可编辑、低置信度提示、断网可手动记账、删除二次确认、空态/骨架/错误态齐全、金额红绿与等宽、连点只产生一条、全面屏安全区、emoji 排版、令牌无写死色值、吉祥物位置、模板无 AI 调用、追问 ≤2 轮、1005 确认、筛选组合、导入预览/撤销、预算不发推送等。
