## 1. 目的与范围

### 1.1 目的

明确本项目的测试策略、测试范围、测试类型、用例设计方法与准入准出标准，确保「一句话记账 → 确认 → 落库 → 统计」核心闭环在功能、性能、安全、兼容性上达到需求规格要求。

### 1.2 测试范围

| 范围 | 内容 |
| --- | --- |
| 纳入测试 | 登录鉴权、AI 解析、账单 CRUD、统计、字典、错误兜底、性能与安全基线；**V2：模板、别名、预算、CSV 导入、多轮补全、搜索筛选与标签、重复检测** |
| 暂不测试 | V3 功能（OCR、共享账本、AA 分账、导出）在对应迭代启动时补充用例；V2 的语音（F-23）与超支推送（F-62）因依赖外部能力（同声传译插件 / 订阅消息模板 ID）**本轮不做** |
| 不在范围 | 微信平台自身能力（登录授权、订阅消息下发）的稳定性，仅验证调用正确性 |

### 1.3 质量目标

| 指标 | 目标 |
| --- | --- |
| 核心用例通过率 | 100%（P0 用例不允许有未修复缺陷） |
| NLP 解析准确率 | 标准用例集（100 条）整体准确率 ≥ 90%；单一字段（金额/渠道/分类）准确率 ≥ 95% / 90% / 85% |
| 接口 P95 响应 | 解析 ≤ 5s；列表与统计 ≤ 500ms |
| 严重缺陷遗留 | 0 |

## 2. 测试策略

### 2.1 分层测试

```mermaid
flowchart LR
    A["单元测试<br/>JUnit 5 + Mockito"] --> B["接口测试<br/>MockMvc / Postman"]
    B --> C["集成测试<br/>真实 MySQL + DeepSeek(可 Mock)"]
    C --> D["端到端测试<br/>微信开发者工具 + 真机"]
    D --> E["验收测试<br/>对照需求规格逐条验收"]
```

| 层次 | 工具 | 覆盖目标 | 责任 |
| --- | --- | --- | --- |
| 单元测试 | JUnit 5 + Mockito | 校验与归一化逻辑、Prompt 构建、工具类 | 开发 |
| 接口测试 | MockMvc / Postman | 全部 V1 接口的正常流与异常流 | 开发 / 测试 |
| 集成测试 | Spring Boot Test + 真实 MySQL | 事务、索引、查询正确性 | 开发 |
| 端到端测试 | 微信开发者工具 + 真机 | 用户真实操作路径 | 测试 |
| 验收测试 | 手工 | 对照《01-需求规格说明书》逐条 | 产品负责人 |

### 2.2 测试重点

1. **AI 解析准确率**（最高风险）：需建立标准用例集，量化评估。
2. **解析失败兜底**：确保任何失败都能完成记账，不出现死路。
3. **统计口径正确性**：按 `record_date` 而非 `create_time`，且与明细勾稽一致。
4. **越权防护**：A 用户不能读写 B 用户的账单。
5. **MySQL 5.6 适配**：emoji 写入、时间字段填充、索引生效。

- 边界数据：金额为 0 / 负数 / 超大值；日期为未来日期；分类为字典外的非法值；文本含 emoji 与超长文本。

## 5. 缺陷管理

### 5.1 缺陷等级

| 等级 | 定义 | 示例 | 处理时限 |
| --- | --- | --- | --- |
| 致命 | 主流程不可用、数据错误或丢失、安全漏洞 | 解析成功但金额算错；越权可读他人账单 | 立即修复 |
| 严重 | 核心功能不可用，但有绕行方案 | 解析接口报 500；统计数值偏差 | 优先修复 |
| 一般 | 非核心功能异常或体验问题 | 分页边界异常；提示文案错误 | 迭代内修复 |
| 轻微 | 样式、文案、优化建议 | 图标错位 | 可延后 |

### 5.2 缺陷生命周期

```
新建 → 确认 → 修复中 → 待验证 → 已验证关闭
                        ↘ 重新打开（验证不通过）
```

### 5.3 缺陷报告要素

标题（含模块与现象）、复现步骤、期望结果、实际结果、环境、日志/截图、缺陷等级、关联需求编号。
