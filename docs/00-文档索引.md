> 本目录为「AI 智能记账小程序」的完整工程文档集，按标准软件工程流程组织：需求 → 设计（含 UI）→ 数据 → 接口 → 测试 → 计划。

---

## 1. 项目一句话简介

用户在微信小程序里输入一句自然语言（如「今天微信买菜支付了100元」），后端调用 DeepSeek 大模型自动解析出金额、收支类型、支付渠道、消费分类、日期，经用户确认后落库，并提供账单管理与统计分析。个人及家庭自用，非商业化。

## 4. 快速开始（M0 准备阶段）

### 4.1 初始化数据库

```bash
mysql -u root -p < docs/schema.sql
```

> 建表 SQL 见《03-数据库设计说明书》§5，初始化字典数据见 §6。建议执行时合并为一个 `schema.sql` 与一个 `data.sql` 归档到《06》§9 的交付物清单中。

### 4.2 后端启动前必配密钥

密钥有两种注入方式，任选其一：

**方式一（本地推荐）**：编辑 `backend/src/main/resources/application-local.yml`（已被 `.gitignore` 排除，不会入库），把 `ai.api-key`、`wx.app-id`、`wx.app-secret` 填上即可。启动时 `dev,local` 两个 profile 会自动加载该文件，无需改动 `application.yml`。

**方式二（生产/规范做法）**：通过环境变量注入，密钥不落在任何文件里。

```bash
DB_USER=root
DB_PASSWORD=<你的数据库口令>
JWT_SECRET=<随机长字符串>
WX_APP_ID=<小程序 AppID>
WX_APP_SECRET=<小程序 AppSecret>
DEEPSEEK_API_KEY=<DeepSeek 密钥>
```

> 本地开发说明：dev 环境已开启 `mock-enabled: true`，不填微信密钥也能完成登录；但**不填 `DEEPSEEK_API_KEY` 时 AI 解析会返回错误码 1002 并回落到手动记账**。微信密钥在真机联调 / 体验版前必须填写，同时把 `mock-enabled` 改为 `false`。

### 4.3 关键配置项

| 配置 | 说明 |
| --- | --- |
| `smartledger.ai.model` | 模型名，默认 `deepseek-flash` |
| `smartledger.ai.read-timeout` | 读超时，默认 12000ms |
| `spring.datasource.url` | 必须带 `characterEncoding=UTF-8&serverTimezone=Asia/Shanghai` |

完整配置见《02-概要设计说明书》§11。
