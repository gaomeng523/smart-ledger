## 1. 通用约定

### 1.1 通信约定

| 项 | 约定 |
| --- | --- |
| 协议 | 开发环境 HTTP；生产环境必须 HTTPS |
| 方法 | 查询用 `GET`，新增用 `POST`，全量更新用 `PUT`，删除用 `DELETE` |
| 编码 | UTF-8 |
| 时间格式 | `yyyy-MM-dd`（日期） / `yyyy-MM-dd HH:mm:ss`（时间戳字段） |
| 金额 | 统一用字符串或两位小数数值传输，服务端以 `BigDecimal` 处理 |

### 1.2 鉴权

除 `POST /api/wx/login` 外，所有接口必须携带 JWT：

```
Authorization: Bearer <token>
```

- token 由登录接口签发，有效期 7 天（配置项 `smartledger.jwt.expire-days`）。
- token 中携带 openid，**服务端一律以 token 中的 openid 作为数据归属依据**，不信任请求体中传入的 openid。
- token 缺失或过期返回 `401`，小程序收到后静默重新登录并重放原请求。

### 1.3 统一响应结构

```json
{
  "code": 0,
  "message": "success",
  "data": { },
  "timestamp": 1791123571000
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| code | int | 0 表示成功，非 0 为错误码 |
| message | string | 提示信息，成功固定为 `success` |
| data | object / array / null | 业务数据；失败时为 `null`，但部分场景会返回可用字段（如解析失败） |
| timestamp | long | 服务端时间戳（毫秒） |

### 1.4 分页响应结构

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "total": 128,
    "page": 1,
    "size": 20,
    "pages": 7,
    "records": []
  },
  "timestamp": 1791123571000
}
```

### 1.5 错误码

| 错误码 | HTTP | 含义 | 前端处理建议 |
| --- | --- | --- | --- |
| 0 | 200 | 成功 | — |
| 400 | 400 | 参数校验失败 | 提示具体字段错误 |
| 401 | 401 | 未登录或 token 失效 | 静默重新登录后重试 |
| 403 | 403 | 越权访问 | 提示无权限 |
| 404 | 404 | 资源不存在 | 提示并返回上一页 |
| 429 | 429 | 请求过于频繁 | 提示稍后再试 |
| 500 | 500 | 系统异常 | 提示稍后重试，记录日志 |
| 1001 | 200 | 微信登录失败 | 提示重新登录 |
| 1002 | 200 | AI 解析失败（超时/服务异常） | 切换手动填表，预填可用字段 |
| 1003 | 200 | AI 输出格式非法 | 同上 |
| 1004 | 200 | 金额无法识别 | 手动补金额 |
| 1005 | 200 | 疑似重复记账 | 弹窗让用户确认是否继续保存 |
| 1006 | 200 | 导入文件格式错误 | 提示支持的文件格式 |
| 1007 | 200 | 解析过于频繁 | 提示稍后再试 |

## 3. V1 接口详细定义

### 3.1 微信登录

**`POST /api/wx/login`**

无需鉴权。

**请求参数**

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| code | string | 是 | `wx.login` 返回的临时登录凭证 |
| nickname | string | 否 | 用户昵称（授权后可选传入） |

**请求示例**

```json
{ "code": "081Xyz0w3xxxxxx", "nickname": "小记" }
```

**响应示例**

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "token": "eyJhbGciOiJIUzI1NiJ9...",
    "isNewUser": true,
    "expiresIn": 604800
  },
  "timestamp": 1791123571000
}
```

**异常**：`1001` 微信登录失败（code 无效或 code2Session 返回错误）。

### 3.3 自然语言解析（核心接口）

**`POST /api/bill/parse`**

只做识别，**不写入数据库**。

**请求参数**

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| text | string | 是 | 用户输入的自然语言，长度 1~200 |

**请求示例**

```json
{ "text": "今天微信买菜支付了100元" }
```

**成功响应**

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "amount": 100.00,
    "billType": 0,
    "payChannelCode": "WECHAT",
    "payChannelName": "微信",
    "categoryCode": "FOOD",
    "categoryName": "买菜餐饮",
    "recordDate": "2026-10-04",
    "remark": "日常买菜消费",
    "confidence": 0.95,
    "needConfirm": true,
    "missingFields": []
  },
  "timestamp": 1791123571000
}
```

**失败响应（AI 不可用，返回可用字段）**

```json
{
  "code": 1002,
  "message": "AI 解析超时，请手动确认",
  "data": {
    "amount": 100.00,
    "billType": 0,
    "payChannelCode": null,
    "categoryCode": null,
    "recordDate": "2026-10-04",
    "remark": null,
    "confidence": 0,
    "needConfirm": true,
    "missingFields": ["payChannelCode", "categoryCode"]
  },
  "timestamp": 1791123571000
}
```

**字段说明**

| 字段 | 说明 |
| --- | --- |
| billType | 0 支出，1 收入 |
| confidence | 解析置信度；`< 0.5` 时前端需高亮提示复核 |
| missingFields | 缺失且必须由用户补全的字段列表 |
| needConfirm | 是否必须用户确认后才可保存（恒为 true） |

**可能的错误码**：`1002`、`1003`、`1004`、`1007`、`400`（文本为空或超长）。

### 3.4 保存账单

**`POST /api/bill/save`**

**请求参数**

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| requestId | string | 是 | 客户端生成的 UUID，用于幂等 |
| amount | decimal | 是 | 金额，必须 > 0 |
| billType | int | 是 | 0 支出，1 收入 |
| payChannelCode | string | 是 | 渠道编码，必须命中字典 |
| categoryCode | string | 是 | 分类编码，必须命中对应收支类型的字典 |
| recordDate | string | 是 | 记账日期 `yyyy-MM-dd` |
| remark | string | 否 | 备注，≤ 255 字符 |
| recordText | string | 否 | 用户原始输入文本 |
| source | int | 否 | 默认 1（文本），语音 2 / 模板 3 / 导入 4 / OCR 5 / 手动 6 |
| confidence | decimal | 否 | 解析置信度 |

**请求示例**

```json
{
  "requestId": "8f3c2b6e-9a11-4d2e-9c77-1a2b3c4d5e6f",
  "amount": 100.00,
  "billType": 0,
  "payChannelCode": "WECHAT",
  "categoryCode": "FOOD",
  "recordDate": "2026-10-04",
  "remark": "日常买菜消费",
  "recordText": "今天微信买菜支付了100元",
  "source": 1,
  "confidence": 0.95
}
```

**响应示例**

```json
{
  "code": 0,
  "message": "success",
  "data": { "billId": 10086, "duplicated": false },
  "timestamp": 1791123571000
}
```

| 字段 | 说明 |
| --- | --- |
| billId | 账单主键 |
| duplicated | `true` 表示因 `requestId` 重复而返回既有记录（幂等命中） |

**可能的错误码**：`400`、`1005`（疑似重复，前端需二次确认）。

### 3.5 账单列表

**`GET /api/bill/list`**

**请求参数**

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| page | int | 否 | 页码，默认 1 |
| size | int | 否 | 每页条数，默认 20，最大 100 |
| month | string | 否 | 月份筛选，格式 `yyyy-MM` |
| billType | int | 否 | 0 支出，1 收入，不传为全部 |
| categoryCode | string | 否 | 分类筛选 |
| payChannelCode | string | 否 | 渠道筛选 |
| keyword | string | 否 | 关键字（匹配备注 / 原始文本） |

**响应示例**

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "total": 128,
    "page": 1,
    "size": 20,
    "pages": 7,
    "records": [
      {
        "billId": 10086,
        "amount": 100.00,
        "billType": 0,
        "payChannelCode": "WECHAT",
        "payChannelName": "微信",
        "categoryCode": "FOOD",
        "categoryName": "买菜餐饮",
        "recordDate": "2026-10-04",
        "remark": "日常买菜消费",
        "source": 1,
        "confidence": 0.95,
        "createTime": "2026-10-04 12:30:11"
      }
    ]
  },
  "timestamp": 1791123571000
}
```

**排序规则**：`record_date DESC, id DESC`（记账日期倒序，同日按插入顺序倒序）。

> V2 起本接口新增搜索筛选参数（金额区间 / 日期区间 / 标签 / 来源），且 `records[]` 增加 `tags`，详见 §4.6。

### 3.6 账单详情

**`GET /api/bill/detail?billId=10086`**

在列表字段基础上额外返回 `recordText`（用户原始输入）与 `updateTime`。

**异常**：`404` 账单不存在；`403` 账单不属于当前用户。

### 3.7 修改账单

**`PUT /api/bill/update`**

请求体：`billId` + 需要修改的字段（`amount`、`billType`、`payChannelCode`、`categoryCode`、`recordDate`、`remark`、`tags`）。

**响应**

```json
{ "code": 0, "message": "success", "data": { "billId": 10086 }, "timestamp": 1791123571000 }
```

**业务规则**：修改后需保证分类与收支类型匹配（收入账单不能挂在支出分类上）。

---

### 3.8 删除账单

**`DELETE /api/bill/delete?billId=10086`**

逻辑删除（`deleted = 1`）。

```json
{ "code": 0, "message": "success", "data": { "billId": 10086 }, "timestamp": 1791123571000 }
```

### 3.9 月度收支统计

**`GET /api/bill/stat/month?month=2026-10`**

**响应示例**

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "month": "2026-10",
    "income": 8000.00,
    "expense": 3250.50,
    "balance": 4749.50,
    "billCount": 62
  },
  "timestamp": 1791123571000
}
```

**业务规则**

- 统计口径为 `record_date` 落在指定月份，**不是** `create_time`。
- 仅统计 `deleted = 0` 的记录。
- `balance = income - expense`。

### 3.10 分类占比统计

**`GET /api/bill/stat/category?month=2026-10&billType=0`**

**响应示例**

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "month": "2026-10",
    "billType": 0,
    "total": 3250.50,
    "items": [
      { "categoryCode": "FOOD", "categoryName": "买菜餐饮", "amount": 1200.00, "ratio": 0.3692 },
      { "categoryCode": "TRAFFIC", "categoryName": "交通出行", "amount": 650.50, "ratio": 0.2001 }
    ]
  },
  "timestamp": 1791123571000
}
```

**业务规则**：`ratio` 保留 4 位小数；前端展示时按需转换为百分比并对尾差做补偿（最大项吸收误差，确保合计为 100%）。

## 4. V2 接口定义

### 4.1 语音解析

**`POST /api/bill/parse/voice`**

请求体在 `/api/bill/parse` 基础上增加 `voiceText`（转写后的文本）。后端逻辑完全复用文本解析链路，便于统一维护。`source` 最终记录为 2。

> 语音转文字在小程序端完成（微信同声传译插件或云端 ASR），后端只接收文本。

### 4.2 模板管理

| 接口 | 方法 | 说明 |
| --- | --- | --- |
| `/api/template` | POST | 新增模板（title、amount、billType、payChannelCode、categoryCode、remark） |
| `/api/template` | GET | 模板列表，按 `useCount DESC, sortNo ASC` 排序 |
| `/api/template` | PUT | 修改模板 |
| `/api/template` | DELETE | 删除模板（逻辑删除） |
| `/api/template/use` | POST | 一键记账：传 `templateId`，后端直接落库，`source = 3` |

**`/api/template/use` 响应**

```json
{ "code": 0, "message": "success", "data": { "billId": 10087 }, "timestamp": 1791123571000 }
```

> 一键记账不经过 AI，因此响应应 < 200ms；同时 `useCount` 自增。

### 4.3 账单导入

**`POST /api/bill/import`**（`multipart/form-data`）

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| file | file | 是 | CSV 文件，≤ 5MB |
| sourceType | string | 是 | `WECHAT` / `ALIPAY` |
| dryRun | boolean | 否 | true 时仅试算不入库，用于预览 |

**响应示例**

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "importId": 3021,
    "totalCount": 320,
    "successCount": 315,
    "failCount": 5,
    "failDetail": [
      { "line": 12, "reason": "金额格式非法" }
    ]
  },
  "timestamp": 1791123571000
}
```

**`POST /api/import/rollback`**：传 `importId`，撤销该批次导入的全部账单（逻辑删除），`import_record.status` 置为 3。

### 4.4 别名词典

| 接口 | 方法 | 说明 |
| --- | --- | --- |
| `/api/alias` | POST | 新增别名映射（keyword、targetType、targetCode） |
| `/api/alias` | GET | 别名列表 |
| `/api/alias` | PUT | 修改 |
| `/api/alias` | DELETE | 删除 |

**生效时机**：解析前先做别名替换；若整句可被别名完全匹配，则跳过 AI 调用（省成本）。

### 4.5 预算管理

| 接口 | 方法 | 说明 |
| --- | --- | --- |
| `/api/budget` | POST | 设置预算（budgetMonth、categoryCode、amount、warnRatio） |
| `/api/budget` | GET | 查询某月预算及使用情况 |
| `/api/budget` | DELETE | 删除预算 |

### 4.6 搜索筛选与标签

**`GET /api/bill/list` 的 V2 扩展参数**（与 §3.5 的 V1 参数叠加，全部可选）

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| amountMin | number | 否 | 金额下限（含），单位元 |
| amountMax | number | 否 | 金额上限（含），单位元 |
| dateStart | string | 否 | 记账日期起，`yyyy-MM-dd` |
| dateEnd | string | 否 | 记账日期止，`yyyy-MM-dd` |
| tag | string | 否 | 按标签匹配；传多个时按 AND 处理 |
| source | int | 否 | 来源筛选（1 文本 / 2 语音 / 3 模板 / 4 导入 / 5 OCR / 6 手动） |

**组合规则**：`month` 与 `dateStart/dateEnd` 互斥，同时传时**以日期区间为准**；`amountMin > amountMax` 返回 `400`；其余条件之间为 AND 关系。

**响应变化**：`records[]` 在 §3.5 字段基础上增加 `tags`（字符串数组，后端按逗号拆分后返回，无标签时返回 `[]`）。

**标签（F-36）语义**

| 项 | 约定 |
| --- | --- |
| 存储 | `bill.tags` 逗号分隔（见《03》§4.4），**不单独建标签表** |
| 约束 | 单条账单最多 5 个标签；单个标签 ≤ 12 个字符；同一账单内去重 |
| 写入 | 随 `/api/bill/save`、`/api/bill/update` 的 `tags` 字段一并提交（数组），**无独立 CRUD 接口** |
| 查询 | `tag` 参数按 `LIKE` 匹配；多标签 AND |
| 复用 | 输入标签时由 `/api/bill/tag/suggest` 联想该用户历史标签 |

**`GET /api/bill/tag/suggest`**

返回当前用户历史使用过的标签，按使用频次倒序，最多 20 个。

```json
{ "code": 0, "message": "success", "data": { "tags": ["出差", "装修", "报销"] }, "timestamp": 1791123571000 }
```

**重复记账检测（F-37）**

不新增接口，由 `/api/bill/save` 在落库前检测：同一 `openid` 下，若存在 `record_date` 相差 ≤ 3 天、`amount` 完全相同、且 `pay_channel_code` 与 `category_code` 均相同的未删除账单，则返回业务码 `1005`，并在 `data.candidates[]` 附上疑似记录。

| 字段 | 说明 |
| --- | --- |
| candidates[].billId | 疑似重复的账单主键 |
| candidates[].recordDate | 该账单记账日期 |
| candidates[].amount | 金额 |
| candidates[].categoryName | 分类名，便于用户辨认 |

前端弹窗二次确认后，带 `force: true` 与**新的** `requestId` 重新提交，后端跳过重复检测直接落库。**必须用户确认，禁止静默拦截**（与 §1 错误码 `1005` 一致）。

**多轮补全（F-25）**

不新增接口。`/api/bill/parse` 已返回 `missingFields`（见 §3.3、§7.2），V2 起前端据此发起追问，**最多 2 轮**；第二轮仍缺失则按 F-52 降级为手动填表（预填已识别字段）。追问与提交均复用同一 `requestId`。

## 5. V3 接口定义（概要）

| 接口 | 方法 | 说明 | 关键约束 |
| --- | --- | --- | --- |
| `/api/bill/stat/trend` ✅ | GET | 近 N 月收支趋势。入参 `range`（仅 6 / 12，默认 6），出参见 §7.4 | items 按时间升序；无数据月份补零；环比/同比基数为 0 或缺失时返回 `null`，禁止除零 |
| `/api/report/month` ✅ | GET | AI 月报。入参 `month`，出参 `{ month, aiEnabled, aiGenerated, summary, highlights[], suggestions[], stats }`（§7.5） | **先由 SQL 聚合出真实 `stats`，再交给模型生成文字**，禁止模型自行算数；AI 关闭/失败时 `aiGenerated=false` 且返回只含真实数字的规则兜底文案 |
| `/api/ocr/receipt` | POST | 上传小票图片，返回 `{ amount, merchant, date, rawText }` | 图片 ≤ 5MB；识别失败返回可手动补全的空结构 |
| `/api/book` | POST/GET/PUT | 创建 / 查询 / 更新账本 | 创建者自动成为 owner 成员 |
| `/api/book/join` | POST | 传 `inviteCode` 加入账本 | 邀请码有效期与人数上限需校验 |
| `/api/book/split` | POST | AA 分账：传 `billId` + `members[]`，生成 `bill_share` 明细 | 分摊金额之和必须等于原金额，尾差归入最后一人；与主账单同事务 |
| `/api/debt` | POST/GET/PUT/DELETE | 借贷记录 CRUD | `settledAmount` 累加后等于 `amount` 时自动置为已结清 |
| `/api/export/bill` ✅ | GET | 导出账单 CSV，入参 `startDate`、`endDate`（均 `yyyy-MM-dd`，可不传） | 流式输出，中文使用 UTF-8 BOM 防止 Excel 乱码；不传日期默认近一年、止期不超过今天；单次上限 10000 条；列：记账日期/类型/分类/支付渠道/金额/标签/备注/原始输入/来源 |

> ✅ 表示 M3 第一批（数据洞察）已实现：趋势报表（F-43）、AI 月报（F-44）、账单导出（F-91）。

### 6.1 微信 code2Session

```
GET https://api.weixin.qq.com/sns/jscode2session
    ?appid={APPID}&secret={SECRET}&js_code={CODE}&grant_type=authorization_code
```

| 返回字段 | 说明 |
| --- | --- |

| session_key | 会话密钥（V1 不使用，不落库） |

### 6.2 DeepSeek Chat Completions

```
POST https://api.deepseek.com/chat/completions
Authorization: Bearer {DEEPSEEK_API_KEY}
Content-Type: application/json
```

```json
{
  "model": "deepseek-flash",
  "messages": [
    { "role": "system", "content": "<PromptBuilder 生成的系统提示词>" },
    { "role": "user", "content": "今天微信买菜支付了100元" }
  ],
  "response_format": { "type": "json_object" },
  "temperature": 0.2,
  "max_tokens": 256,
  "stream": false
}
```

**响应取值路径**：`choices[0].message.content` → 直接作为 JSON 解析。

**注意事项**

- 使用 `json_object` 时，Prompt 中必须出现「JSON」字样，否则接口会报错。
- 模型名从配置读取；`deepseek-flash` 对应 DeepSeek-V4-Flash，官方建议按控制台最新模型列表确认。
- 官方返回的 429 / 500 / 503 统一转换为 `1002` 并对用户做降级处理。
